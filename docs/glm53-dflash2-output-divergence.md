# GLM 5.3 DFlash2 输出差异问题

更新日期：2026 年 10 月 21 日。状态：**未解决，根因尚未完全确认**。

双 Spark 上的 Flare 已接入 DFlash2，文本、图像和选定的服务功能检查通过，但普通解码与 DFlash2 的逐 token 输出一致性检查失败。当前最有证据的解释是目标模型在不同验证宽度下产生数值差异，使接近并列的候选换位；尚未完成完整模型逐层追踪，不能将此推测视为最终根因。

## 环境与影响

- 设备：`spark-01`、`spark-03`，跨机 TP2。
- 目标模型：`GLM-5.3-Flash-EXL3`，保留既有权重、模板和图像输入。
- 客户端入口：NewAPI `8889`；Flare 原生入口：`9999`。
- 部署实现提交：`4fee85e`；首轮原因分析提交：`4d3af4a`。
- 当前包：`/workspace/outputs/flare-beiyu/glm53-exl3-dflash2-tp2-20261021/model.safetensors`。

问题影响逐字复现和与普通解码的等价性判断。尚无完整质量评测可以量化内容质量影响。原有 52 项选定功能检查通过，不能据此认定完整数值等价；在该问题解决并通过正确性验收前，不作正式提速结论。

## 复现条件与现象

使用同一个已导出包进行两组比较：普通组设置 `--mtp-draft-tokens 0`；DFlash2 组使用包默认的自适应验证，最多 7 个草稿 token。此选项是服务启动配置，切换需要协调双机重载。

公开英文提示：

> Write a Python implementation of merge sort, then explain the code line by line in detail.

请求参数为 `temperature=0`、`seed=1234`、`max_tokens=64`，保留默认思考模式。比较消息内容、结束原因及主要 token 用量字段。

最初两个公开提示各重复两次：中文用例两次一致，英文用例两次均从生成 token 索引 `41`（第 42 个 token）开始分叉，差异位于思考内容；token 用量与结束原因一致。因此原始结果为 **2/4 精确匹配，检查失败**。

后续 16 个原生诊断请求中，64-token 输出随验证轮次变化，出现完全匹配、从索引 `41` 分叉、从索引 `55` 分叉三种结果。固定 seed 没有消除该现象。自适应调度选择的验证宽度也受运行耗时影响。

## 已确认的证据

| 检查 | 结果与适用范围 |
| --- | --- |
| 原生目标分数与选择 | 索引 41 的两个相关候选分差出现 0.25、0.125 和完全并列；295 个已记录 token 均选择当时目标分数的最大值，4 次并列均遵循较小 token ID 规则 |
| mHC 残差混合与归一化 | 实际 TP2 rank 0 第 4 层权重、相同合成输入，单行与八行计算有 2/4096 个 BF16 归一化分量不同；最大绝对差 0.0078125，相对 L2 约 0.000246858；发生在任何投机状态提交之前 |
| 编译与捕获 | 上述 mHC 在各自宽度下，编译后的归一化输出与即时执行结果一致；每组输入的 10 次 CUDA 图重放稳定，宽度之间的差异仍存在 |
| KDA 记录与回放 | 三组合成输入中，验证记录阶段保持已提交状态字节不变；接受前缀 1、2、4、8 的回放状态相对误差最高约 2.52×10⁻⁷，未见明显漏恢复现象 |
| 选定的专家与投影 | 真实权重的选定密集层、共享专家、EXL3 专家及 MLA 吸收与展开矩阵乘法首行一致；rank 0 词表投影在宽度 1 至 8、三组输入下均一致 |
| 稀疏 MLA 注意力 | 相同查询、缓存和记录选择下，35/71 条记录一致；257/2051 条记录出现约 0.28% 相对 L2 差异。长上下文结果不能单独解释本次短英文用例 |

诊断请求命中了前缀缓存。因此，先前强制公共前缀请求得到的 0.5 分差，不能当作独立的全新 prefill 参考。组件结果也不能替代完整模型验证，或排除所有状态转换问题。

## 当前判断与后续排查

优先排查的机制是：单 token 解码与多 token 验证的舍入和归约差异经过多层传播，在候选分数接近时改变排序；一次选择不同后，后续上下文不同，文本继续分叉。已观察到这种宽度敏感的组件算术，但**尚未证明本条英文请求首先由 mHC 或其他某个具体算子触发偏差**。

下一步使用相同初始完整状态和固定 token 前缀，逐层对照普通解码与多 token 验证。记录首次偏离的残差、归一化输出、注意力输出、专家路由和最终分数；分别核对验证、拒绝后回放、宽度切换及前缀缓存恢复。保留原始失败结果，不调整参考答案或放宽门槛来获得通过。

修复后的验收应包括原始公开用例、相同前缀的目标分数对照、接受与拒绝后的完整状态、宽度切换、缓存恢复，以及原有文本和图像服务回归。通过正确性验收后再比较性能。
