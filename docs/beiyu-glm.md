# Beiyu GLM compatibility branch

This fork preserves the existing two-Spark GLM deployment as the migration
reference: routed experts remain EXL3 K4 MCG, non-expert and vision weights retain
their original precision, and the same BF16 donor `o_proj` tensors must be used.
The upstream base is `47581ccac82660953a5b59cb04b2750d64edc97d`.

The branch is **not ready to replace the running vLLM service**. No model alias
advertises EXL3 or GLM image serving. The existing upstream GLM recipe continues
to reject images until its encoder and feature-injection graphs are implemented.

## Implemented boundaries

- `qualify/exl3_package.py` isolates the deployed cooperative EXL3 kernel from
  vLLM. It validates the checkpoint encoding and exact binary ABI, captures fixed
  buffers, exports through Flare's production package writer, and runs the
  existing Rust fixed-package checker in a separate process. It deliberately
  uses a single real expert repeated across eight slots. This is a packaging
  mechanism probe, not complete-model, prefill, TP, AOT or performance validation.
- The GLM CPU image frontend includes resize and padding, fused FP32 CLIP
  normalization, 1176-element temporal patches, two-dimensional vision positions,
  image-token layout and upload packing. Nine reference cases were generated by
  the actual deployment processor with CUDA hidden. They cover tiny images,
  padding, downsampling, the 2048-token budget, narrow images, expanded alignment
  and multiple images. The reference is `tests/frontend/glm53_images.json`.
  The source snapshot defaults to 8000 image tokens, while the running service
  caps each image at 2048. Future GLM exports must explicitly prepare the latter
  budget; do not enable the recipe using the snapshot default.
- Requests can explicitly select `stop_scope: "after_reasoning"` for supported
  text-delimited reasoning parsers. It delays string stops until the initial
  reasoning closes. Omitted, null and `"all"` preserve the upstream behavior.
  This setting does not yet have a server/CLI default; clients must set it.
- Checkpoint preflight preserves the F16, I16 and I32 storage types used by EXL3
  and validates their exact byte extents without converting weight payloads.

## Local CPU tests

Python-only checks can run on macOS with Python 3.12. The full preparation extra
is for CUDA/Linux and should not be installed on the Mac just to run these checks.

```sh
uv sync --locked --extra test
uv pip install --python .venv/bin/python \
  'protobuf>=7.35.1,<8' 'cryptography>=46,<52' 'tokenizers==0.23.2' rich filelock
.venv/bin/python -m pytest -q \
  tests/preparation/test_checkpoint.py \
  tests/preparation/test_frontend_metadata.py \
  tests/reference/test_exl3_package.py
```

The upstream native crate uses Linux system interfaces. Use the isolated Linux
image for native CPU tests on macOS. Disk-offload tests use io_uring, which Docker's
standard syscall filter blocks; the relaxed filter applies to this disposable
test container only. No GPUs or model directories are mounted.

```sh
docker build --platform linux/arm64 -f Dockerfile.test -t flare-beiyu:test .
docker run --rm --platform linux/arm64 --cpus 2 --memory 4g \
  --security-opt seccomp=unconfined \
  -v "$PWD:/work:ro" -v flare-beiyu-test-build:/build \
  -e CARGO_HOME=/build/cargo flare-beiyu:test

docker run --rm --platform linux/arm64 --cpus 2 --memory 4g \
  -v "$PWD:/work:ro" -v flare-beiyu-test-build:/build \
  -e CARGO_HOME=/build/cargo flare-beiyu:test \
  cargo run --locked --manifest-path helios/Cargo.toml \
  --features images,test-tools --bin test_glm_images -- tests/frontend/glm53_images.json
```

The broader upstream CLI suite additionally expects the FlashInfer preparation
package, and its repository-case tests require a case-sensitive filesystem. A
minimal macOS test environment does not establish those checks.

## EXL3 GPU qualification

Use a matching Linux preparation environment from `model-preparation.md`. Build
the native checker and select an available SM121 GPU explicitly. The checkpoint
and cooperative library are read-only inputs; the output directory must not exist.
Do not run the probe against the production model's package/cache directory.

```sh
cargo build --manifest-path helios/Cargo.toml --no-default-features \
  --features runtime-package,test-tools --bin test_fixed_runtime_package
CUDA_VISIBLE_DEVICES=0 python -m qualify.exl3_package run \
  --checkpoint /workspace/models/PATH_TO_EXL3_SNAPSHOT \
  --library /PATH_TO_VALIDATED/cooperative_moe.so \
  --output /workspace/outputs/UNUSED_EXL3_PROBE_DIRECTORY \
  --native-executable helios/target/debug/test_fixed_runtime_package \
  --rows 1
```

Repeat with `--rows 32` and both `--tp-rank` values after the smallest case passes.
A successful probe must include native reload/replay, not just Python export.
Production remains in place until the complete target, images and application
behavior have separate parity and service acceptance results.
